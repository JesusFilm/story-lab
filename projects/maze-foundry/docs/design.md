## Scope and decisions

Build a game-independent JavaScript library and standalone inspector in `projects/maze-foundry/`. This is generation tooling; Forge remains the recorded location for MVP game logic. Jerusalem search remains a draft with no approved maze mechanic.

Use a rectangular orthogonal cell graph with seeded generation, optional loops, multiple distinct simple start-to-exit routes, dead ends, route-length and choice-spacing constraints. Express physical dimensions in metres and PNG scale in pixels/metre; report realised dimensions after raster quantisation. Distinguish minimum decision spacing from a maximum uneventful corridor and a first-choice limit. Both are configurable because the user's initial wording and boredom example imply different bounds.

Provide consistent wall thickness and randomly mixed thin/thick segments, with explicit segment overrides for authored gates/buildings. Preserve connectivity while varying footprint. Irregularity initially means wall thickness and stepped footprints on an orthogonal grid, not arbitrary polygons or curved walls.

Verification must independently inspect the raster: connectivity, closed edges/open passages, boundaries and clearance for a square player footprint, in addition to graph criteria. Run bounded adversarial explorers and a multi-seed stress suite. Failed requirements must be visible and block production export; do not silently relax criteria. Random explorers describe behaviour, not proof of fun or guaranteed human difficulty.

## Completed implementation

1. Implemented a dependency-free JavaScript engine with seeded growing-tree generation, useful loops, bounded choice-spacing repair and explicit rejection.
2. Implemented a binary grayscale PNG encoder and versioned JSON manifest, with CLI and sample garden/settlement exports.
3. Implemented independent raster verification, square-player sweeps, adversarial memory traversal, wall followers and seeded random explorers, plus mutation and regression tests.
4. Built a local inspector with config save/load, overlays, wall editing, zoom, traversal replay, cancellation and a 30-seed stress test.
5. Added a macOS launcher, detailed integration contract, saved verification results and workspace navigation.

## Verified results and limitations

15 automated tests pass: determinism, distinct simple routes (including side-loop false positives), exhaustive tiny-graph route comparison, uniform/mixed/one-pixel walls, overrides, 4×4 through 48×48 grids, two- and three-step choice spacing, contradictory inputs, raster topology/clearance, mutated bad maps, replay legality, independent PNG CRC/zlib decoding and optional agent-tool contracts. The preset sweep passed **120/120 mazes** across 20 seeds × three difficulties × two wall modes. [Stress report](../checks/stress-report.json).

The local server and source/asset checks pass; sample PNGs and manifests were generated by the CLI. Browser interaction/visual QA, physical devices and Forge import were not exercised. WebMCP registration/action contracts were tested with a mock registry; no supporting browser registry was available for end-to-end validation. The inspector works without it.

Adversarial tests prove the declared movement/geometry contract; they do not prove fun or empirical difficulty. Irregularity means orthogonal segments with variable thickness and sealed posts, not freeform footprints. Route multiplicity is a minimum of up to four distinct simple routes, not edge-disjoint routes. Numeric presets, actual walk/run timing and final runtime integration remain unaccepted implementation choices.
